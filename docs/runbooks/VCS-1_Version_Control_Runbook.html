VCS-1 / REPRO-1 / REVIEW-1 — Version Control Runbook

All Track A code and access configuration under GitHub from V1, reproducible from a clean checkout, landed only by review

Controls: VCS-1 · REPRO-1 · REVIEW-1 Applies to: Track A (V1) — every version thereafter Repo: npi-datashare (scaffold supplied) Version: 1.0 — 25 Sep 2026

Purpose & the one rule

Every artifact that shapes how NPI is handled — view DDL, the Glue snapshot job, IAM and Lake Formation policies, blueprint state, bucket configuration — lives in GitHub from the first commit. Not because the code is precious, but because the access-control paper trail is: Arctic Wolf review and any Reg S-P question is answered by git log, not by memory.

THE ONE RULE. main.json is the immutable contract. variables.json is the only file edited to change an environment. Templates carry ${VAR} placeholders and never a literal account ID, ARN, bucket, or region. Secrets are referenced by name, never stored — not in variables.json, not gitignored, not anywhere in the repo. CI enforces all of this and fails loud.

The repo model

FileRoleWho edits
main.jsonContract: declared variables, template registry, rules, control mapping. Changing it requires a PR labeled main-json-change with a stated reason; CI blocks otherwise.Rarely — Data Eng + reviewer
variables.jsonPer-environment values. Non-secret only. A value starting with < means "not yet known" and blocks rendering of any template that needs it — a placeholder never ships.Builder, per PR
*.template.jsonPolicies with ${VAR} placeholders. Logic lives here; values do not.Builder, per PR
rendered/Output of render.py. Gitignored. What you paste into the console or feed the CLI.Generated
secrets blockEach entry names where a secret lives (store, ref). A value key fails the render.Builder — references only
Why not a secrets file at all — even gitignored. A file that holds credentials on a laptop is a file that ends up in a commit, a screenshot, or a backup. The GitHub PAT is entered once in the SMUS connection UI and held by AWS. Redshift credentials live in AWS Secrets Manager and are reached by name from Glue and Redshift connections. The repo stores the name. That is the whole design.

What CI enforces on every PR

CheckFails when
JSON parsesAny tracked .json is malformed.
render.py --checkA declared variable is missing; an undeclared one is added; a template references an unknown variable; a secret carries a value; a rendered policy is not valid JSON. Templates waiting on unset values are reported as pending, not failed.
check_no_secrets.pyAnything resembling an AWS key, GitHub PAT, private key, or password literal is committed.
main.json immutabilitymain.json differs from main and the PR lacks the main-json-change label.

Never commit

  • NPI data, sample rows, query results, or screenshots of either.
  • Credentials of any kind — including in a "variables" or "secrets" file, gitignored or not.
  • Rendered output (rendered/) — it contains resolved ARNs and is regenerated on demand.
  • Literal account IDs, ARNs, buckets, or regions inside a .template.json.
